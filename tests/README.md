# 哨務工作台測試包

每次修改工作台之後執行一次，確認規則、排班品質、精算引擎與舊版行為都沒有被改壞。

## 需要

- Node.js 18 以上
- `npm install`（安裝 Playwright），第一次另外執行 `npx playwright install chromium`

## 基本用法

```bash
node run.js 哨務工作台_新版.html
```

全部通過時結束代碼為 0，有任何失敗為 1，可直接放進 GitHub Actions。

## 常用選項

| 選項 | 用途 |
|---|---|
| `--baseline 舊版.html` | 和舊版逐項比對：個人事件禁排、班與班衝突、塞錯班表的巡檢結果必須完全相同（巡檢比較會先把舊版班表套到新版，排班演算法改變時也能比）。 |
| `--quick` | 略過最耗時的「嚴重不足 22/14」情境（約省 50 秒）。 |
| `--leave 休假.tsv --door 56 --officer 56` | 用真實休假紀錄排班並驗算（名冊以 H001…、P001… 編號產生）。 |
| `--write-golden 標準答案.json` | 把這次真實資料的排班結果存成標準答案。 |
| `--golden 標準答案.json` | 和標準答案逐班比對；任何一班不同就失敗。演算法刻意改變時，請重新寫入標準答案。 |
| `--expect-exact-variants` | 要求規則參數變體也必須由精算引擎證明最優。v7.9.5 起精算引擎直接讀規則表，建議一律加上。 |
| `--report report.json` | 輸出詳細結果。 |
| `--only burden,equivalence` | 只跑指定的項目（selftest、demo、stress、variants、settings、burden、equivalence、real）。 |

## 測什麼

1. **內建規則自測**：工作台本身的自測必須全部通過。
2. **範例名冊**：一鍵排班 0 缺班、巡檢 0 項、獨立驗算 0 項；同資料重排結果相同；大門、安官精算的主要目標（缺班、班數公平等）都要證明最優。勤務負擔點數（每哨最多 180 秒）與假日班公平（60 秒）屬次要項，未完成證明時保留找到的改善，屬正常。
3. **驗算器自我檢查**：故意塞入違規，確認驗算器抓得到。
4. **壓力情境**：大量休假、人力吃緊、大單位、嚴重不足。
5. **規則參數變體**：自動改規則表數值（休息 8 小時、最多連站 1 天…），確認排班結果符合新數值。
6. **設定頁**（v8.2 起）：在「排班規則與每人上限」改休息時數後排班須符合新設定，重新開啟後設定仍在。
7. **勤務負擔點數**（v9.0 起，設定為點數模式時）：統計表的「勤務點數」須與獨立計算一致；封存本月後，下個月的「點數累計差額」須等於上月實得減應得，且下月整體往平衡方向修正。
8. **新舊版等價**（指定 `--baseline` 時）。
9. **真實資料回歸**（指定 `--leave` 時）。

「獨立驗算」由 `lib/verify.js` 執行：它只讀規則表的數值，判斷邏輯自行實作，不使用工作台內的排班判定或巡檢程式。工作台本身因此有三套各自寫成的規則判讀（排班判定、獨立巡檢、本驗算器），三者必須一致。

## 注意

- 測試時會把一行偵錯掛鉤注入**暫存副本**，原檔不會被修改。
- 真實休假或名冊資料請勿上傳到公開儲存庫或 CI；只在本機以 `--leave` 使用。
- 通過測試代表「符合規則表」，不代表規則表本身符合單位規章；規章仍需人工逐條核對。
